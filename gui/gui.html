Hình dung GUI

GUI = cả cửa sổ desktop (layout), không phải từng widget lẻ. Hướng dẫn trực quan tiếng Việt + mock hai màn Dashboard / Cấu hình chuột.

Vì sao GUI khó hình dung hơn component?

Component docs (nút, slider…) giống ảnh từng chiếc ghế. GUI là ground plan phòng khách — bạn cần thấy ghế đặt ở đâu, cửa ở đâu, TV ở đâu cùng lúc.

    Trạng thái thiết bị trong GUI

    1. 1.
      Connected (Đã kết nối)

      Giao diện đầy đủ độ sáng; mọi control ghi được (trừ khi firmware quá cũ).

    2. 2.
      Disconnected / Sleeping

      Grey-out vùng cấu hình phần cứng; banner “Kết nối thiết bị” hoặc “Nhấn phím bất kỳ để đánh thức”.

    3. 3.
      Firmware updating

      Khóa customization; progress %; cảnh báo không rút dây / không tắt thiết bị — modal hoặc full-width banner.

    4. 4.
      Error / Low battery

      Cảnh báo đỏ/vàng góc dễ thấy; pin yếu ≤15% gợi ý sạc; lỗi link tới retry/diagnostics.

    Ánh xạ lên component DS

    • Connected → Connection badge success + canvas opacity 100%
    • Sleep → badge idle + canvas read-only
    • Updating → badge updating + global overlay + progress component
    • Low battery → Battery widget error + optional toast

    Nguyên tắc UX

    Zero perceived latency, tooltip giải thích thuật ngữ, dark mode mặc định.

    Zero perceived latencyĐổi LED/nút → thiết bị đổi ngay hoặc nút Apply rõ + onboard memory.
    Plain languageTooltip giải thích polling, debounce — không chỉ thuật ngữ thô.
    Dark defaultNền tối, RGB và accent nổi; tránh chói khi dùng lâu.

    Độ trễ cảm nhận bằng 0

    • Lighting: stream preview tới device khi có bandwidth; nếu không — spinner ngắn rồi apply
    • Remap/DPI: debounce ghi firmware; hiển thị “Đang lưu…” trên đúng control
    • Nút “Apply to onboard memory” tách biệt với “Save profile on PC”

    Đơn giản hóa thuật ngữ

    Ví dụ tooltip: Polling rate — “Tốc độ báo vị trí chuột; cao hơn = mượt hơn, có thể tốn pin hơn.”

    Debounce time — “Bỏ qua rung phím/nút trong X ms — hữu ích cho switch cơ.”

    Dark mode mặc định

    Token nền #111 / panel #1F1F; chữ primary/secondary; accent chỉ trên control active và hotspot selected. Light mode optional cho văn phòng / y tế.

    Nền tảng & đối tượng

    Design System giữ nguyên component; shell và copy thay theo sản phẩm — chọn dimension khi implement.

    Key points
    • Windows / macOS desktop (Synapse, G Hub) — layout 3 vùng, chuột + bàn phím
    • Mobile BLE companion — dashboard + ít slider, pin/signal quan trọng hơn
    • Embedded touch trên thiết bị — canvas = chính mặt thiết bị, sidebar thu gọn
    • Gamer vs văn phòng vs công nghiệp/y tế — jargon tooltips bật mức “pro” hoặc “plain”

    Color

    Primary brand, neutral surfaces (dark-first), and semantic colors tied to device state. Gaming utilities often fix #111111 / #1F1F1F — see Case study tokens.

    Key points
    • Primary — brand accent (slider thumb, active nav)
    • Connected / updating / error / warning
    • Optional data-product-theme for Razer / Logitech accents

    Typography

    Inter, Segoe UI, or Roboto — clear hierarchy for dense settings. Tabular figures for DPI and polling values.

    Key points
    • Title / section / body / caption / mono data
    • 11–14px body in sidebars
    • 16–20px panel titles

    Spacing & grid

    4px base, 8px rhythm — consistent padding in sidebar rows and control groups.

    Key points
    • 4, 8, 12, 16, 24, 32
    • Align labels to 8px grid
    • Min 12px between unrelated groups

    Interaction states

    How controls look across default, hover, active, focus-visible, disabled, loading, and device-pending.

    Key points
    • Never remove focus ring on desktop utilities
    • Disabled = lower contrast + no pointer events
    • Loading blocks duplicate device writes

    Error & disconnect

    Behavior when the HID link drops or firmware fails — banners, modals, toasts.

    PredictableSame disconnect pattern everywhere in the app.
    RecoverableTell user what to do: replug, wake device, retry pairing.
    Non-destructiveKeep unsaved profile locally until user discards.

    Device disconnected

    When the HID device is unplugged or link lost mid-session:

    1. Show sticky banner below header — semantic error background.
    2. Disable Apply, sliders, and visualizer writes; allow export profile.
    3. Toast optional for transient blips (<2s); banner for sustained loss.

    Firmware & errors

    • Modal for failed flash — do not close silently.
    • Progress component with cancel only when safe.
    • Log link for support (copy diagnostics).

    Toast vs modal

    Toast: profile saved, minor retry success. Modal: data loss, firmware failure, incompatible device.

    GUI vs Design System

    GUI is the house users live in. The Design System is the blueprint, standard bricks, and paint rules so every floor uses the same materials.

    • Same DPI slider on Performance tab and onboard memory tab
    • Same disconnect banner everywhere — not one screen custom-hacked
    • Accent only on active controls and selected device regions

    DPI slider

    Not a generic range input: snap to allowed steps, show min/max labels, optional stage presets (400 / 800 / 1600).

    Saving configuration

    When DPI or remap changes, show inline spinner on the control (or row), then green check + “Saved to device memory” — not a blocking modal for success.

    • Failure: keep spinner → error icon + retry
    • Debounce rapid slider drags before HID write storm
    • Disable Apply while a write is in flight
