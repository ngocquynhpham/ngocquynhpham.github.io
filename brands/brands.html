Color

Standardized Quinn color and usage guidelines. A formal system keeps the brand consistent and easier to recognize across TV UI.

Standardized colorDefined service colors and usage rules for the Quinn brand.
Consistent experienceA formal color system keeps UI predictable and strengthens brand recognition.
TV-first validationTest on real displays — TV contrast and gamut differ from web.

Principles of use

Color testing on TV

TV screens have higher contrast than typical web monitors, so intended colors can look different. Higher saturation reads brighter and more vivid, so test across display settings and models.

Displays render color with RGB sub-pixels. Cool tones (blues) often reproduce more reliably. White balance and color temperature settings shift overall hue; many TVs are tuned with green as reference, so warm tones can appear more sensitive.

sRGB & DCI-P3

sRGB and DCI-P3 describe the gamut a TV can reproduce. sRGB is the most common and compatible across the widest range of sets.

DCI-P3 can look richer for video; content authored in P3 may not translate on all TVs and is best treated as a premium-display target.

  • Prefer colors with clear lightness contrast and restrained saturation on UI chrome.
  • Avoid assuming web-calibrated swatches will match living-room viewing.

Brand color

Brand color unifies the product and supports recognition — follow the token rules below.

Quinn is content-first: do not sprinkle arbitrary hues; use specified chips for UI chrome.

  1. 1.
    Three chip families

    Use the three recommended Quinn brand chip families (primary, secondary, accent roles).

  2. 2.
    Stay on-brand

    Avoid unrelated hues outside the defined palette.

  3. 3.
    Buttons & complement

    Primary actions use brand color; complementary hues may pair for contrast on CTAs.

  4. 4.
    Dark theme hierarchy

    On dark UI, combine low-saturation brand tones with point color to clarify layers.

TV white color

High TV contrast makes white appear especially bright. Lower luminance in tokens reduces eye strain during long sessions.

TV dark theme

Dark theme cuts glare, improves legibility, and keeps attention on content.

  1. 1.
    Point color visibility

    Use bright (low-sat / pastel) or vivid (high-sat) accents so focus and CTAs read on dark backgrounds.

  2. 2.
    Avoid harsh saturation

    Very saturated large fields on dark UI can halo or vibrate — limit area.

  3. 3.
    Small accent areas

    Apply point color to narrow regions (focus rings, badges, key CTAs).

  4. 4.
    Comfort over decoration

    If accent coverage grows too wide, reduce saturation or area.

Color palette

  1. 1.
    Primary color

    Hero brand hue. Core UI that defines the Quinn experience must stay within primary chips.

  2. 2.
    Gray color

    Neutral ramp for structure and typography — mostly text and subtle surfaces.

  3. 3.
    Background color

    Full-screen backdrop; usually derived from primary/secondary neutrals, sub tones when needed.

  4. 4.
    Dimmed color

    Scrim over content for modals and overlays — opacity-based tokens.

  5. 5.
    Alert color

    Errors, warnings, and critical system messages.

Usage color guide

Order color by information priority — the most important message should win contrast first.

Brand font

Type carries brand identity and keeps visual consistency. Use Quinn’s defined family, styles, and color pairing so users recognize the product at a glance.

Quinn TV uses Quinn Sans as the shared brand typeface — tuned for LED and large displays with optimal spacing and legibility at viewing distance.

Supports Korean, Latin, and numerals. Weights: Bold, Medium, and Light.

  1. 1.
    Weight

    Stroke weight minimizes clumping on LED panels and avoids a cramped, overly heavy look.

  2. 2.
    Legibility

    Straight segments on the letterforms are widened so shapes read cleanly on screen.

  3. 3.
    Identity

    Bottom-left skeleton rounding on select glyphs gives Quinn a distinct, recognizable brand character.

Hierarchy

Type emphasizes important information and builds visual hierarchy. Use headline, title, body, and supporting styles to show structure and priority.

Combine weight, style, color, and placement to guide attention so users find what they need quickly on ten-foot UI.

  1. 1.

  2. 2.

  4. 4.
    Label

Iconography

Pictograms for faster recognition on TV. Grid, stroke, color, states, and naming rules for Quinn icon assets.

Intuitive symbolsFamiliar pictograms explain function faster than text on ten-foot UI.
Grid & strokeFixed grid, stroke weight, and corner rules keep sets visually balanced.
Shared state tokensEnabled, selected, focused, and disabled apply the same tokens everywhere.

Overview

Icons use familiar, simplified shapes to express features and context more intuitively than copy alone — helping users understand Quinn TV at a glance.

Icon design

When drawing or exporting icons, follow these rules so the set feels cohesive on LED and living-room displays.

  1. 1.
    Visual weight

    Balance optical weight across icons so none feel heavier or lighter than its neighbors in the same context.

  2. 2.
    Stroke width

    Unify stroke width between 3px and 4px at the master artboard scale.

  3. 3.
    Corners

    Set corner radius per icon so the shape reads clearly — do not force one global radius if it fights the metaphor.

  4. 4.
    Slant

    Apply tilt only when the metaphor needs it (e.g. play, send); keep most UI icons upright.

Grid

Work inside a fixed grid and keylines so icons align on screen with consistent balance and visual weight.

Size

Author icons at 48×48px as the master asset. Ship one source file per icon and scale down or up in UI — do not redraw per density unless platform requires it.

Color

Default icon color is Quinn TV white (#F5F5FF). When an icon needs a distinct hue, export a separate colored asset — do not rely on runtime tinting that breaks token parity.

States

Every icon supports the same four states. Apply the defined design tokens consistently — do not invent one-off treatments per screen.

  1. 1.
    Enabled

    Default active icon — available for interaction.

  2. 2.
    Selected

    User has chosen this icon (e.g. toggle on, current tab).

  3. 3.
    Focused

    D-pad or pointer focus so the user can see where they are on screen.

  4. 4.
    Disabled

    Unavailable — reduced contrast per disabled token.

Naming rules

Name assets with the rules below so engineering and design can find and ship icons predictably.

  1. 1.
    Lowercase only

    Use US English lowercase a–z, underscore _, and digits 0–9. No other characters.

  2. 2.
    Start with a letter

    The first character must be a–z. Do not start with a digit or underscore.

  3. 3.
    No hyphens

    Spaces are not allowed. Separate words with underscore _, not hyphen -.

  4. 4.
    File extension

    Use .png when alpha is required; use .jpg when the image has no transparency.

Name structure

Build each filename from prefix, root, and optional suffix segments.

  1. 1.
    Prefix

    Asset type defines what the resource is. Namespace defines where it appears — omit namespace for icons reused across screens; add it only for icons tied to a specific surface or subclass.

  2. 2.
    Root

    A noun that best describes the icon (e.g. search, home, settings).

  3. 3.
    Suffix

    If prefix + root is ambiguous or collides with another asset, append the minimum extra segments in the order shown in the naming diagram.

Layout

Structural template for visual consistency. Grid, spacing, and regions define where information and UI live — tuned so content reads well on TV.

Structural templateKeeps visual consistency across Quinn TV screens.
Grid & spacingDefines columns, gutters, and regions for UI and content.
Content-firstLayout choices should optimize how information and media read on TV.

Composition

Screen layout definition

Baseline structure for Quinn streaming UI on Android TV — rails, safe areas, and page shells.

Rule

  1. 1.
    Resolution

    Unlike web or mobile, TV is fixed 16:9. Design at 1920×1080 so elements scale proportionally on HD and 4K.

  2. 2.
    Unit

    Layout values in px should land on even numbers for cleaner scaling and alignment.

  3. 3.
    Safe zone

    Keep critical UI inside safe margins so overscan on older TVs does not clip content. Use 40px top/bottom and 72px left/right unless platform overrides apply.

Grid

Each column has a fixed width; content aligns to defined columns for predictable rhythm and stable focus paths.

Quinn Android TV uses a 12-column grid — column width 114px, gutter 20px (adjust in tokens when platform requires).

Type

Pick a grid type based on screen role — each type maps to a layout template.

  1. 1.
    Default

    Standard browsing and content rails.

  2. 2.
    GNB

    When global navigation is expanded or primary.

  3. 3.
    Synopsis

    Detail / synopsis screens with metadata and actions.

Arrange pattern

Lay out for D-pad movement: focus order should follow natural remote directions.

  1. 1.
    A. Horizontal

    Default rail — items in a row, left-aligned; groups tiles and controls.

  2. 2.
    B. Vertical

    Stacks content vertically; groups text-heavy blocks and lists.

Quinn Assist

LLM multi-turn assistant for media — conversational search with entry from dock, search, banners, and voice.

Media LLMMulti-turn dialogue specialized for media and entertainment.
Conversational searchFind and explore content through natural language.
Voice-first entryDock, search, banners, and remote mic / wake phrase.

Overview

Quinn Assist is an LLM-powered assistant focused on the media content domain. It supports multi-turn conversation, interactive content discovery, and voice-led navigation across the Quinn TV experience.

How to open Assist

  1. 1.
    Dock menu

    Launch from the dock menu icon.

  2. 2.
    Unified search

    Enter via the assistant action on unified search.

  3. 3.
    Merchandising banner

    Tap through featured placement in browse surfaces.

  4. 4.
    Voice invocation

    Remote microphone key or platform voice input (e.g. FFV).

Voice UI

Voice chrome communicates agent state: icon shape and helper copy change per state so users get clear feedback during voice input and responses.

Agent states

  1. 1.
    Mic idle

    Microphone is closed — default waiting state.

  2. 2.
    Mic active

    Listening for user speech; no utterance detected yet.

  3. 3.
    User speaking

    User speech is being captured.

  4. 4.
    Analyzing

    Utterance finished; system parses intent and generates a reply.

  5. 5.
    Assist speaking

    Answer is playing — TTS audio for the message region is active.

Voice UI by state

Icon, on-screen copy, focus behavior, and STT bubble rules per agent state.

Mic idle

  • Voice chrome icon: state-specific asset (see design spec).
  • Voice chrome copy: “Press the voice search key on your remote, or say ‘Hey Quinn…’ and ask your question.”
  • Focus: shown normally.

Mic active

  • Voice chrome icon: state-specific asset.
  • Voice chrome copy: “Go ahead — I’m listening.”
  • Focus: hidden.

User speaking

  • Voice chrome icon: state-specific asset.
  • Voice chrome copy: live partial utterance text.
  • Focus: hidden.
  • STT bubble: stream recognized speech in a right-aligned bubble in real time.

Analyzing

  • Entered when speech ends, until a reply is ready.
  • Voice chrome icon: state-specific asset.
  • Voice chrome copy: dimmed version of the last utterance.
  • Focus: hidden.

Assist speaking

  • Voice chrome icon: state-specific asset.
  • Voice chrome copy: not shown (answer body carries content).
  • Focus: shown normally.

Style

Shape and size combine to express visual priority on TV.

Shape

Container shape defines the family. Square → higher importance than Rounded for the same size tier.

Size

Height tiers: Large > Medium > Small (importance follows the same order).

Icon

  • Use icons only when meaning stays obvious at ten-foot distance.
  • Do not stack icon and label vertically inside one button.
  • Fixed 8px gap between icon and label.
  • One icon per button.
  • Icon color is flat; state colors come from tokens.

Container

Text labels must sit inside a container (solid fill or equivalent token treatment).

  • Width grows with label length; min horizontal padding per size tier.
  • Content is center-aligned (except time-mapping and key button layouts).
  • Container fill is solid; state colors from tokens.

Usage

Combine icon and label so the action is scannable on a TV screen.

  • Prefer a short label when it is clearer than an icon alone.
  • Labels are concise nouns — not full sentences.

Buttons

tvOS actions with Quinn tokens — same anatomy, states, and types as Android TV where possible.

StyleVisual layer: size, color, and shape.

TypesFunctional meaning of the button; type influences which style to use.

Elements that may appear in a button. All variants use the same token set.

  1. Icon (optional)
  2. Text label
  3. Container

  1. Text label
  2. Time count
  3. Container

Key button

  1. Text label
  2. Key icon
  3. Container

Icon button

  1. Icon
  2. Container

States

Definition of elements per button. All state visuals use the same tokens.

  1. 1.
    Enabled

    Default interactive button — ready for input.

  2. 2.
    Selected

    The user has chosen this button (when selection applies).

  3. 3.
    Focused

    D-pad / remote focus is on this button.

  4. 4.
    Disabled

    Inactive — action unavailable.

Types

Types depend on what the button includes and when to use each pattern.

  1. 1.
    A. Common button

    The default pattern for primary actions.

  2. 2.
    B. Time mapping button

    Use when the action is tied to time (elapsed or remaining).

  3. 3.
    C. Key button

    Includes guidance for a specific remote key.

  4. 4.
    D. Icon button

    Use when an icon alone is intuitive enough.

Style

Shape and size combine to express visual priority on TV.

Shape

Container shape defines the family. Square → higher importance than Rounded for the same size tier.

Size

Height tiers: Large > Medium > Small (importance follows the same order).

Icon

  • Use icons only when meaning stays obvious at ten-foot distance.
  • Do not stack icon and label vertically inside one button.
  • Fixed 8px gap between icon and label.
  • One icon per button.
  • Icon color is flat; state colors come from tokens.

Container

Text labels must sit inside a container (solid fill or equivalent token treatment).

  • Width grows with label length; min horizontal padding per size tier.
  • Content is center-aligned (except time-mapping and key button layouts).
  • Container fill is solid; state colors from tokens.

Usage

Combine icon and label so the action is scannable on a TV screen.

  • Prefer a short label when it is clearer than an icon alone.
  • Labels are concise nouns — not full sentences.
  • Label must match the action; no extra metadata in the label.
  • Use loading/disabled patterns so users know work is in progress — not a mistaken tap.
