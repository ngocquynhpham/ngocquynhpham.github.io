Quy tắc ownership (quan trọng)
  • page.tsx mỏng — Gọi data function, pageMeta, bọc layout width, gắn JsonLd. Không map field API trực tiếp trong page.
  • data/api là contract nội bộ — Đổi Swagger chỉ sửa đây + regen client. UI không được import FrontNewsroomSelectResponse trực tiếp.
  • data/mock = fallback + UI config — Types, constants, UI config + fallback shape + content chưa/không lên API (financial tables, ESG diagrams).
  • lib = cross-cutting thuần — seo, routes, bbs helpers, cache, assetPath. Không có business logic.

🔌 Data Layer
Pattern vàng — copy sang bất kỳ dự án Next.js nào. Ba lớp cache phải nắm rõ.
Pattern chuẩn (getNewsroomPage)
export const getNewsroomPage = cache( // Layer 1: React cache() — dedupe 1 request async (query: NewsroomQuery = {}): Promise<Paged<NewsStory>> => { try { return await ttlCache(cacheKey, async () => { // Layer 2: in-memory TTL const { data } = await api.api.page1({ ... }); return toPaged(data.data, (item) => toStory(item, tabs)); }, CACHE_TTL.long); } catch (error) { logApiError("[api] GET /api/v1/newsroom failed", error); return emptyPage<NewsStory>(); // Graceful degrade } }, );
Ba lớp cache
LớpCơ chếPhạm viKhi nào đủ
React cache() Dedupe trong 1 render Cùng function gọi 2 lần trong 1 request → 1 fetch Luôn dùng
ttlCache In-memory TTL + stale-while-revalidate Per Node process — N instance EC2 = N cache riêng 1–2 instance, đơn giản
force-dynamic Không static HTML at build Mọi page hit server; no build-time HTML Footer/legal luôn mới
Owner checklist khi scale
  • Tăng số instance EC2 → hit rate cache giảm, API load tăng → xem xét Redis
  • Deploy rolling → cache cold mỗi process → tăng TTL hoặc dùng ISR
  • Muốn shared cache → Redis (chưa có trong repo) hoặc ISR/fetch revalidate
  • API down → site không crash → UX có thể trống (emptyPage) → là product decision
WAF Workaround (nợ kỹ thuật)
⚠️ Kỹ thuật nợ cần biết

lib/api.ts: Server-side fetch dùng User-Agent Chrome cố định vì WAF CloudFront chặn UA không phải browser. Fix đúng: allowlist IP origin server hoặc dùng private ALB thay vì public API.

BBS Domain (lib/bbs.ts)

  • toPaged → chuẩn hóa list/pageNum/pages/totalCount cho mọi board
  • Date: API YYYY-MM-DD → hiển thị YYYY.MM.DD
  • Thêm board mới: copy pattern boardResolution.ts, không invent pagination mới
⚡ Request Flow
Vòng đời một request trong Next.js 16 App Router — từ edge đến client islands.
5 bước xử lý một request
Step 1
Edge/Node nhận request → route match app/
Không có middleware.ts → không redirect/auth tập trung. SEO redirect nằm hết trong next.config.ts.
Step 2
Root layout.tsx (force-dynamic)
Parallel fetch getFamilySites() + getFooterLegalLinks() → Header/Footer luôn fresh mọi request.
Step 3
Nested layout (optional)
CompanyShell, GovernanceShell, EsgLayout (client tabs) — chỉ khi section cần active nav.
Step 4
page.tsx fetch + render RSC HTML
Gọi data/api functions, pageMeta, JsonLd. Render HTML trên server và stream về.
Step 5
Client islands hydrate
Breadcrumb dropdown, news filter/pagination (URL state ?tab=&q=&page=), modals, charts. URL state tốt cho share link.
Luồng dữ liệu đầy đủ
page.tsx (RSC) └─► data/api/*.ts (adapter) ├─► lib/api.ts → api-client/index.ts → Backend API ├─► data/mock/ (fallback / tĩnh ESG) └─► ttlCache / React cache()
Client navigation (NewsContent)
  • Dùng useRouter + searchParams — filter là URL state (?tab=&q=&page=)
  • Tốt cho share link, back/forward button hoạt động đúng
  • SEO: generateMetadata set index: false khi có ?q= → tránh thin content

GEO — Generative Engine Optimization (không phải geolocation)
🤖 Tối ưu cho LLM crawler
  • public/llms.txt: mô tả site, URL chính thức, quy tắc trích dẫn cho AI (tránh URL cũ menu_id, không coi ?q= là trang chính thức)
  • robots.ts: liệt kê rõ GPTBot, ClaudeBot, PerplexityBot, Google-Extended với rule allow/disallow
  • Đây là tư duy mới — site lớn cần chuẩn bị để LLM cite đúng URL
Owner Playbook — thêm route mới
  1. Thêm entry seoPages.newPage trong seo.ts
  2. Export metadata = pageMeta(seoPages.newPage) trên page.tsx
  3. Nếu cần schema → helper JsonLd + inject trong page
  4. Redirect URL cũ nếu thay slug
  5. Verify sitemap (static tự vào qua Object.values(seoPages))
  6. Noindex khi có query string (?q=) để tránh thin content
🤖 AI trong dự án — thực tế là gì?
Tách biệt AI trong sản phẩm vs AI trong workflow phát triển.
Trong sản phẩm (website)
Không có AI runtime trong app
  • Không có MCP, không gọi OpenAI/Anthropic trong codebase
  • "AI" = nội dung marketing: block "AI 미디어", popup AI B tv (AiBtvPopupModal)
  • Runtime = SSR/RSC + REST API backend thuần, không chatbot/embed model
AI trong workflow dev (IDE level)
✅ Cursor + Claude (bạn dùng)
  • Design-to-code từ Figma Dev Mode
  • Component scaffolding tự động
  • Code review inline
  • Giảm đáng kể thời gian implementation

Đây là IDE-level tool, không phản ánh kiến trúc runtime của site.

AGENTS.md trong repo

Block Next.js 16 do next dev inject — hướng dẫn agent (Cursor, Copilot) đọc docs trong node_modules/next thay vì hallucinate API cũ.

Pattern hay: để AGENTS.md guide AI agent hiểu đúng version framework.

MCP — có không?
Không có MCP trong codebase

Không có cấu hình MCP, Cursor rules (.cursor/), hay orchestration "băm task" trong code. MCP/Figma là môi trường IDE của dev, không phải kiến trúc của product.

Tuy nhiên — GEO (llms.txt + bot rules) là cách site nói chuyện với AI crawlers. Đây là tư duy AI-native ở layer content, không phải runtime.

Bài học cho dự án tiếp theo
  • AI trong workflow (Cursor) ≠ AI trong product — tách biệt khi nói chuyện với client
  • GEO (llms.txt) nên là standard cho brand lớn từ ngày đầu
  • AGENTS.md là pattern tốt để guide AI agent hiểu đúng version framework đang dùng
  • Nếu cần AI runtime thật (chatbot, RAG): cần thêm API layer riêng, không nhúng trực tiếp vào corporate front

🔒 Security
Public corporate site — attack surface nhỏ nhưng có vài điểm cần chú ý.
Attack surface (không có auth)
⚠️ XSS từ CMS HTML

HtmlContent + dangerouslySetInnerHTML. Không có sanitize library trong repo. Cần security review nếu CMS admin bị compromise.

⚠️ Dependency audit

CI chỉ block ở critical. Dependencies cần review định kỳ. npm audit không phải silver bullet.

Headers đã có
  • X-Frame-Options: DENY — ngăn clickjacking
  • Referrer-Policy — kiểm soát referrer leak
  • Permissions-Policy — tắt geolocation API trình duyệt
  • CSP Report-Only — chưa enforce, đang collect violations
  • GTM third-party → cần trong CSP allowlist khi enforce
  • Không secrets trong repo — API public read-only phía front
Client hygiene

instrumentation-client.ts + script gỡ attribute extension (bis_skin_checked) gây hydration warning — pattern hay để giữ hydration clean khi user có browser extensions.
